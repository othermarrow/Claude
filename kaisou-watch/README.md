# 階層目録を Amazfit Balance 2 で遊ぶ（kaisou-watch）

階層目録（`backrooms-pwa/`）の六つの札すべてを、一つのミニアプリ「階層目録」（Zepp OS）にまとめたもの。
起動画面で札を選ぶと、そのゲームが開く。話・仕掛け・結末は階層目録と同じ（時計では、画面の演出と音は出ない）。スマホとの通信はいらない。

| 札 | ゲーム | 元 |
|---|---|---|
| 記録 01 | ノークリップ | `backrooms-pwa/games/noclip.html` |
| 記録 02 | 野帳（振動つき） | `backrooms-pwa/games/yacho.html` |
| 記録 03 | 未定稿 | `backrooms-pwa/games/miteiko.html`（`tools/build-miteiko.js` で、画面の処理を切り離して作る） |
| 記録 04 | 空欄_2 | `backrooms-pwa/games/kuuran2.html`（時計版の `kuuran2-watch/` の本体を写す） |
| 記録 05 | 蔵守 | `backrooms-pwa/games/kura/*.js` と `kuramori.html` の配色・場所の表（`tools/build-kuramori.js` で、本体と世界を束ねて、ほかと同じ口に包む） |
| 記録 06 | 控室 | `backrooms-pwa/games/hikae.html` |

蔵守は、ほかの五本と作りが違う（問いに「はい／いいえ」で答える場面があり、命令を作るときの「物」が動詞ごとに変わる）ので、画面にも、問いの答えのボタンと、動詞ごとの物の一覧を足した。

## 画面

- **起動画面**：四つの札（番号・題・一行・結末の数・いちばん深いところ・何周目か）。押すと、そのゲームが開く。ゲームを遊んだあと戻ると、要約が更新される。
- **ゲームの画面**（どれも同じ作り。画面を上下にスクロールして使う）
  1. いまいる場所と、一行（階層・SAN・記録・体温など、ゲームごと）
  2. 直前までの命令（3つ）と、今の命令と、その結果
  3. 「命令を作る」：動詞 → 物（→ 2つ目の物）、「言う」「書く」はことば、の順にタップする
  4. 方角（上・北・西・見る・東・南・下）。行ける方角だけ明るい
  5. よく使う命令（ゲームごと）
  6. 振動の入／切、「はじめから」（3秒以内に2回押す）、「階層目録へ」（起動画面に戻る。時計の「戻る」＝右へのスワイプでも戻れる）

文字の入力はない（全部タップで遊べる）。色は、ゲームの階層・区画ごとに、HTML 版と同じ。

## 保存

- 1手ごとに自動で保存する。アプリを閉じても、次に開くと続きから遊べる。
- 時計のアプリ用の場所に、ゲームごと（`noclip` `yacho` `kuuran2` `hikae`）に `<名前>.json`（状態）・`<名前>-loop.json`（周回の記録。はじめからやり直しても残る）・`<名前>-meta.json`（起動画面の要約）を置く。`kaisou-set.json` は振動の入／切。アプリを消すと一緒に消える。
- スマホの階層目録の保存や、`kuuran2-watch`・`yacho-watch` の保存とは、つながっていない。

## 準備（初回だけ）

前提：Termux に Zepp OS の開発ツール `zeus` が入っていて、`minamo-watch` などを `zeus preview` で送れていること。

```bash
cd ~/Claude && git pull --no-rebase --no-edit origin main
cd ~/Claude/kaisou-watch
bash setup.sh
zeus preview
```

`setup.sh` が部品（`node_modules`）を入れる。これを飛ばすと、時計で開いたときに真っ暗になることがある。表示された QR コードを Zepp アプリ（開発者モード）で読み取ると、時計に入る。

## 補足

- `app.json` の appId `1098790` は、ほかの時計アプリと重ならないようにした仮の番号。時計に送るときに「ダウンロードエラー（400）」になったら、この番号が原因のことが多い。時計に入っている別のアプリの番号（`kuuran2-watch` の `1098772` など。**同じ番号のアプリは上書きされる**）に変えると入ることがある。
- アプリの大きさは、ソースで約 900 KB（ゲーム本体 4 本で約 880 KB）。Zepp OS の上限は確かめていない。大きすぎて入らないときは、ゲームを一本ずつ外す（`app.json` の `pages` と `page/<ゲーム>/` を消す）。
- 起動画面はゲーム本体を読み込まない（札の要約だけ読む）ので、開いたゲームの分だけがメモリに載る想定。実機では確かめていない。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `page/index.js` | 起動画面（札） |
| `page/<noclip|yacho|kuuran2|hikae>/index.js` | ゲームごとの設定（配色・一行・よく使う命令）だけ。画面は `shared/gamepage.js` |
| `shared/gamepage.js` | ゲームの画面（文章・方角・命令を作る・よく使う命令）。四本とも同じ |
| `shared/engines/*.js` | ゲーム本体。`tools/build-engines.js` で自動で作る（直接は直さない） |
| `shared/themes.js` | noclip と hikae の配色。HTML 版の CSS から自動で作る |
| `shared/store.js` | 状態・札の要約・設定の保存 |
| `shared/ui.js` `shared/vibe.js` | 部品を置く小さな道具・振動（ほかの時計アプリと同じ） |
| `tools/build-engines.js` | 本体と配色を作り直すスクリプト（未定稿は `tools/build-miteiko.js`、蔵守は `tools/build-kuramori.js`） |
| `setup.sh` | 初回の準備（`npm i`） |

## HTML 版を直したとき

`backrooms-pwa/games/` のゲームを直したら、リポジトリ全体を置いた場所で次を実行して、本体と配色を作り直す。

```bash
node kaisou-watch/tools/build-engines.js
```

空欄_2 だけは、`kuuran2-watch/shared/engine.js` を写すので、先に `node kuuran2-watch/tools/build-engine.js` を実行する。

## 確かめたこと

- 1.2.0：蔵守（記録 05）を追加。六本すべてで、ランダムな操作を各 1,500 回、例外なし。蔵守は、問い（選ぶ場面）・結末（八つのうち、一つ以上）・「ひとつ戻す」・開き直して続きから・札の要約（最深「三晩目」）まで動いた。**蔵守は、画面の演出（電気がいなくなる停電・水の音・夜の揺れ）が出ない。文章と仕掛けは同じ。実機では、まだ見ていない。**

- 1.1.0：未定稿（記録 03）を追加。起動画面の札の左の余白を広げ、「▶」（時計の字体になく絵文字になっていた）をやめた。未定稿を含む五本で、ランダムな操作を各 1,500 回。その中で、空欄_2 の本体に、周回の記録を書く関数が抜けていて、結末の近くで止まる不具合が見つかり（`kuuran2-watch` の時計版も同じ）、`kuuran2-watch/tools/build-engine.js` を直して作り直した。

- 1.0.1：実機で、起動画面の札が黒く塗りつぶされて文字が見えなかった（札に重ねた透明のボタンが、札を黒く塗っていた）。題の行をそのままボタンにして、重ねるのをやめた。偽の部品の上で、四つのボタンがそれぞれのゲームへ移ることを確かめた。**直ったかは、まだ時計で見ていない。**

開発環境の node で、Zepp OS の部品（画面・保存・移動・振動）を偽物に置き換えて、四本のゲームの画面を本物のまま動かした：ランダムな操作（方角・よく使う命令・命令を作る（動詞 → 物 → 2つ目の物・ことば））を、一本につき 1,500 回、合計 6,000 回。例外なし、画面の文字に「undefined」や埋まっていない欄がないこと。結末に着いたあとの「はじめから」と、周回の記録が残ること。開き直して続きから遊べること。起動画面の札の要約（結末の数・最深・周目）が書かれて、読まれること。四つの札を押すと、それぞれの画面へ移ること。

**実機（Balance 2）では、まだ確かめていない。** 文字の大きさ・画面の色・スクロールの速さ・アプリの大きさの上限・メモリ・振動の強さ・「階層目録へ」（`back()`）で戻れること・起動画面の札の押しやすさは、送ってみて確かめる。
