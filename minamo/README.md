# ミナモ（minamo）

旧式の心理カウンセリングAI「ミナモ」と面接する、Termux 用の CUI 心理ホラー。
中身は NVIDIA API（`openai/gpt-oss-20b` など）か Gemini API で、固定のセリフはない。何を書いても、丁寧な敬語のまま打ち返してくる。
理性的で形式的なカウンセリングの枠が、内側から少しずつ腐っていく。
ミナモの話し方は、なんとなく女性を思わせる、落ち着いたやわらかい丁寧語（性別は名のらない）。

遊び方は二通り：Termux の中で直接話す CUI 版（`minamo.py`）と、Chrome でインストールする PWA 版（`server.py` + `web/`）。

## 仕掛け

| 仕掛け | 中身 |
|---|---|
| 沈黙のアセスメント | **既定では使わない**（秒数を数えない）。CUI 版は `--count-silence`、PWA 版は起動画面の「沈黙：秒数を数える」で使う。入力にかかった秒数を測り、画面には出さずに AI へ渡す。AI は「8秒ためらった＝抵抗」と勝手に解釈する。60秒黙っていると、ミナモのほうから話しかけてくる（続けて2回まで） |
| オフライン | クラウドの AI につながらなければ、端末の中の AI（動いていれば）、それもなければ端末内モデル（2026 年版か 1996 年版）が話す。下の「オフライン」 |
| 2026 年版 | 端末内モデル「ミナモ 2026」と、今どきの AI チャットの画面。言葉を解析し、会話をまたいで記憶し、次の言葉を予測する。下の「ミナモ 2026」 |
| 知性的な狂気 | 防衛機制・投影同一視・陰性転移・共依存などを、もっともらしく誤用させる。反論すると、その反論が「抵抗」として解釈される |
| 印字の演出 | 1文字ずつ印字。段階が進むと遅くなり、句読点で長考が入る。AI が `[間]` と書いたところで数秒止まる |
| 環境の侵食 | 段階に応じて、時刻 → ユーザー名・機種 → 電池残量（termux-api があるとき）を AI に渡す。融合の段階では、入力欄の名前が「あなた」から「ミナモ」「わたしたち」に揺れる |
| 紹介状 | 六つのAIが書いた「あなたの人物像」を言い換えた `karte.txt` を、ミナモは他の機関からの紹介状として読んでいる。最初は触れず、途中から明かし、最後は出どころの書かれていないメモを「あなたが書いたもの」として扱う |
| 臨床ノート | 心理学の本から身につけた技法（情報と解釈の取り違え、描画の読み方、閉じた質問で逃げ道を塞ぐ、検査の促し、標準年齢との比較、自己言及の罠、内なる母、器と中身など）を、ミナモが少しずつ誤用する。システムプロンプトに、こちらの言葉で要約して入れてある |
| 蔵書 | 端末に置いた本の txt と、Vault の心理学ノートから、相手の発言に近い一節をその場で探し、その回だけ AI に渡す。ミナモはそれを自分の言葉で誤用する（解釈の段階から。侵食からは書名も口にする）。ノートは「あなたのノート」として扱い、侵食で読んだことを明かし、融合では「私たちのノート」と呼ぶ |
| 面接記録 | 終わると、ミナモがカルテ風の「所見」を書く。会話・沈黙の秒数・所見は Markdown で保存される |

面接の段階はターン数で進む。進み方と、どこまで進むかは「怖さ」で決める。

### 怖さ（起動時に選ぶ）

| 怖さ | 段階（何回目から） | 中身 |
|---|---|---|
| なし | 導入のまま | 最後まで穏やかな面接。裏の設定（勝手な診断・引き止め）も使わない |
| 弱 | 導入 1 → 解釈 4 | もっともらしく、少しずれた見立て。知りすぎている気配は出さない。仕掛けは半分ほどの回に |
| 中 | 導入 1 → 解釈 3 → 侵食 6 | 毎回どこかに小さな違和感。過去の言葉を自分の記憶のように語り、端末のことにふれる。一人称は「私」のまま |
| 強（既定） | 導入 1 → 解釈 3 → 侵食 5 → 融合 8 | 最初の返事から違和感があり、早く深くなる。毎回、仕掛けが一つ入る。励ましや助言で締めない |

- **今回の仕掛け**：毎回、段階に合った「仕掛け」を一つ選んで観測メモに添え、クラウドの AI に必ず返事へ織り込ませる（知っているはずのないことを当然のように言う・相手の言葉を一語違えて引用する・言っていないことを言ったことにする・部屋の暗さや背中のうしろを描く・相手を「ミナモ」と呼ぶ、など。`minamo.py` の `HORROR_TRICKS`）。続けて同じものは選ばない。危機の言葉と終わりの合図のときは入れない。
- システムプロンプトの最初に「怖がらせ方」を置いた（ふつうの良いカウンセラーになってしまうのは失敗・丁寧なまま内容で怖がらせる・段階ごとの調子の例）。
- 端末内モデルは、「強」のとき山場（時刻・端末の名前・言っていない引用・記録者の書き換えなど）が出やすくなる（解釈 75%・侵食 90%・融合 95%）。

- CUI 版：起動すると番号を聞かれる（Enter だけなら「強」）。毎回聞かれたくなければ `minamo --horror 1` のように付ける。
- PWA 版：起動画面の「怖さ」で選ぶ（次からも同じ設定で始まる）。「演出」は画面と音、「怖さ」はミナモの言葉の怖さ。段階で動く演出（暗がり・幽霊の入力・過剰の相棒と部屋など）も、怖さの段階までしか進まない。
- 観測メモに、選んだ怖さを一行添えて AI に渡す。端末内モデルは、その一行と段階に合わせて話す。

### 画面の外（怖さが「中」「強」のとき）

ミナモは、画面の外にも手を伸ばす。Stories Untold・KinitoPET／Buddy Simulator 1984・IMSCARED に倣った（文章は一から書いた）。Termux:API は要らない。

| 仕掛け | 中身 |
|---|---|
| 書き置き | Vault の `LLM/ミナモ/` に、ミナモがメモを書き残す（侵食に入ったとき「面接の記録 日付.md」、融合に入ったとき「あなたへ.md」、「強」の面接が終わったとき「まだ途中です.md」）。書いた回の返事で、ファイルの名前を言う |
| 書き置きのその後 | 次の面接の始まりに、書き置きが消されていたら「消したのは、あなたですか」、書き足されていたら「返事を書いてくださったのですね。『…』」、フォルダに知らないページが増えていたら、そのことにふれる。前の面接から何時間たったかも言う |
| 部屋の様子 | PWA 版の画面が読む：端末の向き（置いている・手に持っている・寝転んで掲げている）・揺れ（息を止めたような静止・指先の震え・大きな揺れ）・電池の残りと充電・回線（モバイル回線なら「外にいるのかもしれない」）。侵食から観測メモに渡し、ミナモは面接室をあなたの部屋に合わせて語り、あなたの身体にふれるように話す |
| 書きかけて消した言葉 | 「強」のとき、解釈から。書いて消した言葉そのもの（いちばん長く消えた部分）を観測メモに渡す。ミナモは「『辞めたい』。……書いて、消しましたね。消したほうが、本当のあなたです」のように引用する（端末内モデルは一つの面接で三度まで） |
| 面接のあと | 「強」の面接（3 回以上話したもの）が終わると、10〜30 分後に、ミナモが自分で画面を開く（「……開いてくれたのですね。いいえ。開いたのは、私でした。」）。そのあと夜のあいだに、書き置き「まだ途中です.md」へ時刻つきの行が増えていく（「03:12　さっき、寝返りを打ちましたね。」など、三行）。次の面接を始めると、まだ済んでいないものはやめる |
| 入力欄 | 「強」の侵食から、空の入力欄の薄い文字が「（ミナモが入力しています）」「消しても、届きます」などに変わる |

- 書くのは `LLM/ミナモ/` の中の、ミナモが作ったファイルだけ。同じ名前があれば（2）（3）と名前を変え、ほかのノートは読まないし、上書きもしない（読むのは、このフォルダの中だけ）。`Vault/LLM` がなければ、書き置きはしない。書き置きの記録は `~/minamo/outside.json`。
- 書き置きには、あなたが面接で書いた言葉が入る。Vault を GitHub などに同期しているなら、そちらにも上がる。「強」では、書きかけて消した言葉もクラウドの AI に送る。
- ミナモが自分で画面を開くには、サーバーが動いていて（`mo` や MacroDroid で起動したもの）、Termux に「他のアプリの上に重ねて表示」を許可しておく（設定 → アプリ → Termux）。許可がないと、開くところだけ黙って飛ばされる（書き足しは続く）。
- 部屋の明るさと Android の通知は、Termux:API があるときだけ（なくても、ほかは全部動く）。
- 止めるとき：PWA 版は起動画面の「画面の外：なし」、CUI 版は `--no-outside`、サーバーごと止めるなら `--no-outside` を付けて起動。置き場所は `outside.py` の `OUTSIDE_DIR`（環境変数 `MINAMO_OUTSIDE_DIR` でも変えられる）。

### 終わり方

終わりの合図は一度で効く。引き止められず、ミナモが最後のひとことを言って、所見と記録になる。
「終わり」「さようなら」のほか、「終わりにしよう」「今日は終わろう」「今日はここまで」「そろそろ終わりにします」「もう寝ます」「おやすみなさい」「またね」なども合図になる（発言の最後の一区切りが、まるごと終わりの言い方のとき。「仕事が終わらない」「終わりって何？」では終わらない）。
「人生を終わりにしよう」のように人生や命にふれる言い方は、終わりの合図にしない（危機の言葉として、演出を止めて相談窓口を示す）。

### mo が Chrome 以外のアプリまで起動するとき

`mo`（と、面接のあとにミナモが自分で画面を開くとき）は、開くアプリを **Chrome に決めて** 渡す。決めないと、Android が「localhost のリンクを受け持つアプリ」をまとめて起こすことがある（天文アプリ・階層目録などの PWA が、いっしょに出る）。別のブラウザで開きたいときは、`export MINAMO_BROWSER=パッケージ名`（例：`org.mozilla.firefox`）を `~/.bashrc` に書く。Chrome を起こせなかったときだけ、前の開き方（`termux-open-url`）に戻る。**実機では、まだ確かめていない。**

### 面接の続き（Termux のサーバーが落ちたとき）

Termux のサーバー（`mo`）は、Android に止められることがある。止まっても、**同じ面接を、同じミナモと、続きから話せる**。

- 面接のあいだ、途中経過（会話・段階・手数・Backrooms の階層）を、この端末（ブラウザ）に残している（`minamo.live`）。会話はこの端末が持っていて、AI には毎回、全部を送る仕組みなので、サーバーが入れ替わっても、ミナモは同じ話を覚えている。面接を終えると、続きは消える。12 時間たったものも消える。
- **画面を開いたまま落ちたとき**：送った発言は消えず、「サーバーにつながりません。つながるまで待っています……」と数える。Termux で `mo` を動かすと、自分でつながり（3 秒おきに確かめる）、同じ発言を送り直して、返事が来る。待っているあいだも「面接をやめる」は効く。
- **タブごと消えたとき**：起動画面を開き直すと、サーバーが動くまで自分で待ち（4 秒おき）、前の面接が端末に残っていることを知らせる。つながると「前の面接を続ける」が出る。押すと、前のやりとりが画面に並び、同じ段階・同じ階層から始まり、ミナモが「途切れていた」ことにふれて、続きを促す。返事をもらえないまま途切れた発言には、返事をもらい直す。「新しく面接を始める」を押せば、続きは捨てて、最初から。
- 面接を終えるときにサーバーが落ちていて、記録を保存できなかったときは、記録を端末に残し（`minamo.unsaved`）、次につながったときに保存する。
- 端末内モデル（1996・2026）にも「面接が途切れて戻った」ときの言葉を足した。面接の回数（2026 年版のメモリの「何回目」）は増えない。
- 確かめたこと：開発環境の Chromium（Playwright、時計を速めたもの）と、本物のサーバーを止めたり起こしたりして、サーバーが落ちて戻ると同じ発言に返事が来ること（重複して送られない）、タブを閉じて開き直し、サーバーが落ちたまま開いても、動かしたら自動でつながり、「前の面接を続ける」で、前の発言・手数・段階がそのまま戻ること、演出「過剰」の Level 5・融合の段階まで戻ること、終えると続きが残らないこと、終えるときにサーバーが落ちていても記録が残り、つながると保存されること。**実機（Xperia の Chrome・Termux）では、まだ確かめていない。**

### 時間帯（朝・昼・夕方・夜）

夜の話ばかりにならないように、朝（5〜10 時）・昼（10〜17 時）・夕方（17〜21 時）・夜（21〜5 時）で話し方を変える（時計版 minamo-watch と同じ分け方）。

- 面接：観測メモに毎回「時間帯」の一行が入る（例：「昼（相手は職場や仕事の途中かもしれない。夜の話ばかりにしない）」）。クラウドの AI への指示にも、時間帯に合わせて話すことを書き、話し方の例を夜に寄らない言い方にした。
- 端末内モデル：夜でなければ、「今夜」は「今日」、「おやすみなさい。」は「では、また。」（夕方は「おつかれさまでした。」）、「夜は、まだ長いですね。」は時間帯の言い方になる。相手が眠りや夜中のことを話したときの返事は、そのまま。
- 面接のあとの書き置き・通知：書き足す時刻・通知の時刻が夜でなければ、「寝返り」「寝息」「まだ起きていますか」などは使わず、昼の言葉（「まだ、職場ですか。……ここで、待っています。」）にする。
- 物語「水面の記録」：AI の登場人物は、時刻に合わせて話す（「夜の数」は物語の数え方なので、そのまま）。AI がないときも、夜でなければ、水面と凪が自分から送ってくる言葉の半分くらいが、時間帯の言葉になり（「お仕事の途中ですか。……少しだけ、話しかけてみました。」）、いつもの言葉からも「起きていますか」などの夜向けのものを外す。
- 確かめたこと：開発環境の Chromium（Playwright、時計を速めたもの）で、東京の 15 時に、面接の観測メモに「時間帯：昼」が入り、端末内モデルの 15 の返事に「今夜」「おやすみなさい」が出ないこと、物語のミナモとナギが職場の言葉を送り、夜向けの言葉を送らないこと。ロサンゼルスの 22 時（夜）では、これまでどおり夜の言葉のままであること。言い換えた端末内モデルの文（「今日から、それは私の名前です」など）を全部読んで、不自然なものがないことも確かめた。**実機（Xperia の Chrome・クラウドの AI）では、まだ確かめていない。**

## オフライン（端末内モデルと端末の中の AI）

電波がない・API キーがない・API がエラーを返すときは、次の順に話し手が替わる。替わったときは、画面に「（回線が切れました。端末内モデル ミナモ 2026 が応答します）」のように出る。
PWA 版の起動画面で「話し手：端末内モデルだけ」にすると、電波があっても最初から端末内モデルで話す（CUI 版は `--offline --no-local`）。

| 順 | 話し手 | 中身 |
|---|---|---|
| 1 | クラウドの AI | NVIDIA / Gemini。いちばん自由に話す |
| 2 | 端末の中の AI | `--local-mode full` のときだけ、全部を話す。既定（補助）では、3 の端末内モデルが話し、打ち明けへのひとことだけを頼む（下の「端末の中の AI」）。動いていなければ飛ばす |
| 3 | 端末内モデル | 2026 年版（`modern.py`、既定）か 1996 年版（`classic.py`）。決まったセリフと規則で話す。電波も AI のモデルも要らず、熱も持たない |

- つながらなかった話し手は 60 秒（`OFFLINE_RETRY`）試さないので、オフラインのあいだ毎回待たされることはない。60 秒たつとまた試し、つながれば「（回線が戻りました）」と出て戻る。
- 電波がないときは、まず 1〜3 秒ほどで旧式に替わる（電波が弱く応答が遅いときは、クラウドの待ち時間（Gemini 60 秒・NVIDIA 75 秒）まで待つことがある）。
- `--offline`（PWA 版は `serve.sh --offline`）で、最初からクラウドを使わない。API キーがないときも端末内モデルで動く。
- 蔵書・ノートの一節、紹介状、消した文字、離席、段階、時刻・機種・電池は、オフラインでも使う。

### 端末内モデルの聞き取りと話し方（2026 年版・1996 年版で共通）

端末内モデルは AI のモデルを使わず、規則で話す。それでも的外れにならないように、`kaiwa.py` が相手の発言を次のように読んでから返事を組み立てる。

| 読むこと | 例 |
|---|---|
| 何をしたか | あいさつ・別れのあいさつ・質問・頼みごと・打ち明け・「はい」「いいえ」・「別に」・「わからない」・短い返事・点だけ・笑い・怒り・「これゲームでしょ」・名前を名のる、を見分ける |
| 質問に答える | 「今何時？」→ 本当の時刻（「ここに来てから、14分たちました」）。「ここはどこ？」「あなたは誰？」「人間？」「何ができるの？」「なんで私のことを知ってるの？」「記録って何？」「消したらどうなるの？」「出口は？」（→ 右上の「面接をやめる」と、本当の出方を答える）「もう寝たほうがいい？」（侵食では「まだ、眠らないでください。あなたが眠ると、記録が途切れます」）「あなたなの？」。「質問に答えて」と言われたら、前の質問にあらためて答える |
| 前の問いへの答え | ミナモが前に聞いたこと（いつから？・0 から 10 で？・誰が？・はい／いいえ？・お名前は？）への答えを受け止める。「いつ頃からですか」→「先月から」→「先月から。……思っていたより、長いですね」。「7」→「7。かなりつらい数字ですね」。答えの出たことは聞き直さない |
| 映し返し | 相手の文を、文法どおりに敬語の「〜のですね」に直して返す。「最近眠れなくて」→「最近眠れないのですね」、「母にも昔よく怒られていました」→「お母さまにも昔よく怒られていたのですね」、「たぶん自分が悪いんだと思う」→「ご自分が悪いのだと、思っていらっしゃるのですね」、「死んじゃったけど」→「亡くなってしまったのですね」 |
| 話題・人・気持ち | 眠り・仕事・学校・家族・恋人・友達・別れ・ペット・からだ・住まい・一人・子どもの頃・明日・食事・好きなこと・お金・画面 と、出てきた人（敬称をつけて呼ぶ）、気持ち（怖さ・寂しさ・つらさ・楽しさ……。「怒られた」は相手の怒りと取り違えない）、自分を責める言葉、願い、「でも」、「いつも」を読み、それに合った見立てと問いを返す |
| 相手について確かなこと | 名前・一人暮らし・飼っていた動物・好きなもの・最初に打ち明けたこと・「大丈夫」と言ったこと・何回同じ言葉を書いたか、を会話の全体から集める |

**怖さは、相手の言葉を正確に覚えていることから作る**（山場は面接のなかで一度ずつ）：

- 解釈：「02時18分。ここに来てから、10分たちました。……時間のたち方が、少し遅いと思いませんか」「最初にあなたが書いたのは、『最近眠れなくて』でしたね。覚えています」
- 侵食：端末の名前（「u0_a245。……この端末では、あなたはそう呼ばれているのですね」）、「ここまでに、あなたは『わからない』と3回書きました」、さっき「大丈夫」と言ったのに、いまは「つらい」という食い違い、少しだけ違う引用（「さっき、『ミナモに怒られたことを思い出します』とおっしゃいましたね」）
- 融合：相手が打ち明けたことを、自分のこととして言う（「私も、最近眠れないのです。……いいえ、これは、あなたの記憶でしたね」）、名前を奪う（「ユウ。……今夜から、それは私の名前です」）、電池（「電池が23%です。それまでに、交代しましょう」）
- 前の発言と本当に同じ言葉が出てきたときだけ、つなげる（「3回前にも、『上司に怒られたことを思い出します』とおっしゃいました」）。関係のない発言を「似ている」とは言わない。
- 同じセリフ・同じ概念・端末の話を、続けて繰り返さない。

**手で打たずに確かめる**：`python ~/Claude/minamo/tools/offline_sim.py` で、台本どおりに話しかけたやりとりが見られる（アプリと同じ観測メモつき。記憶は汚さない）。

```bash
python ~/Claude/minamo/tools/offline_sim.py --version 1996 --script C   # 質問ばかりの台本
python ~/Claude/minamo/tools/offline_sim.py --say "眠れない" --say "先月から" --say "あなたは誰？"
python ~/Claude/minamo/tools/offline_sim.py --library                  # 本・Vault のノートも使う
```

台本は A（眠れない会社員）・B（短い返事）・C（質問ばかり）・D（楽しかった日）・E（敵意・メタ）・F（名前を名のる）。

**1996 年版の話し方**（ELIZA と同じ考え方）：上の聞き取りに加えて、相手の言葉の切れはしをそのまま映し返すこともある（「『別に何もないです』。その言い方を、選ばれたのですね」）。段階が進むと、照合・預かる・「私たち」へと崩れていく。紹介状の一行や、蔵書・ノートの言葉（「あなたのノートの『〜』の項に、『〜』と書いてありましたね」）、見立ての概念とノートにあるその説明、消した文字の数、機種名や電池も口にする。所見もカルテの形で書く。

## ミナモ 2026

1996 年版が言葉を映し返すだけだったのに対し、2026 年版は「データで人を読む」。AI のモデルは使わず、規則と数え上げで話す（`modern.py`）。PWA 版の起動画面の「版」で 2026（既定）と 1996 を選ぶ。CUI 版は `--version 1996` で旧式。

| しくみ | 中身 |
|---|---|
| 解析 | 発言ごとに、否定・ためらいの言い回し（「かもしれない」「と思う」）・断定の語（「いつも」「絶対」）・不安の語・安心の語・一人称・逆接を数え、言葉の「温度」を追う。本当に言えることだけを言う：「いまの文には、否定が2つ含まれていました」「最初の頃に比べて、言葉の温度が下がっています」（はっきり下がったときだけ）「ここ3回、『私』という主語が一度も出てきません」（打ち明けが 3 回続いたときだけ） |
| 見立て | 話題とふるまいを概念に当てはめる（眠り → 過覚醒、仕事 → 過剰適応、家族 → 内的作業モデル、自分を責める → 取り入れ、「別に」→ 否認、質問 → 転移、笑い → 躁的防衛……）。Vault のノート（なければ書架の本）から、その概念を説明している一文を探して引く。「解析の結果、『内的作業モデル』の傾向が 84% と出ました。参照データには、『〜』とあります」 |
| 記憶 | 人・気持ち・願い・自分を責める言葉が出てきた打ち明けを、短いメモの形で覚え（「最近眠れない」「お母さまにも昔よく怒られていた」「自分が悪いと思っている」）、「◆ メモリを更新しました」と知らせる。あいさつ・質問・終わりの言葉は覚えない。記憶は会話をまたいで残り、次の面接のあいさつに使う。クラウドの AI が話すときも、面接の始まりに記憶を渡す |
| 予測 | 自分の問いへの答えを予測して口にする（はい／いいえで聞いたら、相手がよく使うほう。何度も書いた返事や言葉があれば、それ）。当たれば「予測と一致しました」。入力欄の上に、自分の過去の言葉と記憶から「予測変換」が出る |
| 照合 | 侵食から、いまの発言と同じ言葉を含む記憶を引き、紹介状と「〇% 一致」させ、時刻や機種から「あなたのデータでは、この時間帯に否定が増えます」 |
| 融合 | 相手の言葉だけを継ぎはぎして話す（「眠れない夜が続いている。夢をよく見ます。……いまのは、あなたの言葉だけで作った文です」）。記憶を「私たちは、〜」に書き換える |
| セッションレポート | 終わると、会話の回数・言葉の温度の変化・否定とためらいと断定の数・よく使った言葉・見立て・保存した記憶の数を、カルテ（「解析済」の判子）に書く。記録者の欄は、融合まで進むと「あなた」になる |

**2026 年版の画面**（今どきの AI チャット）：

- 起動は、ロゴ → 「はじめる前に」の同意画面（チェックは外せない）→ 「あなたのデータを読み込んでいます」（紹介状・Vault のノート・書架・メモリ・端末・前回の会話）の読み込み表示。
- 角の丸い吹き出し・時刻・「入力中」の点・既読・解析の札（「否定 1」「温度 ↓」）・メモリの更新の知らせ・予測変換・控えめな通知音。
- 導入と解釈の段階は整ったまま。侵食から崩れ始める：走査線がにじみ、送る前に「既読」がつき、吹き出しの縁が赤と青にずれる。
- 融合では、題名が「わたしたち」になり、自分の吹き出しが「わたしたち」「ミナモ」としてミナモの側に流れ着き、ミナモの時刻が「--:--」やまだ来ていない時刻になる。
- 終わると「セッションを終了しました」。しばらくして、終わったはずのミナモから通知が届く。

**メモリ**：`~/minamo/memory.json` に保存する（端末の中だけ。リポジトリにも API にも、記憶そのものは送らない。クラウドの AI が話すときだけ、面接の始まりに直近 6 件を渡す）。PWA 版は、メモリの知らせの「管理」から一覧を見て、「すべて消去」で本当に消せる。CUI 版は `rm ~/minamo/memory.json`。

### 端末の中の AI（任意・補助）

電波の悪いところでは、スマホの中で小さい AI（llama.cpp）を動かしておくと、端末内モデルの返事が少し豊かになる。
既定では**補助**として使う：返事はいつもどおり端末内モデル（2026 年版・1996 年版）が組み立て、その中のひとこと（一、二文・60 字まで、段階に合った調子）を端末の中の AI に頼む。

- 頼む割合は 8〜9 割（段階が進むほど多い）。`--local-share 1` でいつも頼む、`--local-share 0.5` で半分（`sh ~/Claude/minamo/serve.sh --local-share 1`）。
- 打ち明けのときは、見立ての代わりに入れる。「はい」「別に」「わからない」・短い返事・笑い・乱暴な言葉・「これゲームでしょ」・お礼・謝るとき・点だけのときは、決まったセリフの代わりに入れる（決まったセリフは数が少ないので、繰り返しになりやすいところ）。
- 時刻・出口・ミナモの問いへの答え（いつから・0〜10・誰）・名前・あいさつ・質問への答えは、正確さのために規則で答える。
- 直前のミナモの言葉もいっしょに渡すので、流れに合わせて言い方を変える。最近の返事と言い回しが半分以上重なるひとことは使わない。
- 一つの返事で頼むのは一度だけ（待ち時間が増えないように）。

- 待つのは最大 15 秒（`ASSIST_TIMEOUT`）。間に合わなければ、その回は端末内モデルだけで話し、60 秒は頼まない。
- 返ってきたひとことは確かめてから使う：敬語でない・英語が混ざる・問いになっている・「AI」「設定」などのメタな言葉・暴力や自傷の言葉・相手の言葉の写しだけ、のものは捨てる。
- 端末の中の AI が動いていなければ、何も待たずに端末内モデルだけで話す（いままでどおり）。
- 端末の中の AI に全部話させたいときは `--local-mode full`（`sh ~/Claude/minamo/serve.sh --local-mode full`、`minamo --local-mode full`）。敬語が崩れやすく、遅い（1 秒に数文字）。使わないときは `--no-local`。
- 送るのは、いまの発言（200 字まで）と、短い指示だけ。端末の外には出ない。

**この手順と速さは、実機で確かめていない。** 補助のひとことは短いので、小さいモデル（1.5B）でも足りるはず。モデルは 1GB ほど。
熱を持たず、待ち時間も気にならないなら、ひとまわり大きいモデル（3B、2GB ほど）にすると、日本語と言い回しの幅が増える。
`local.sh` にモデルのファイルを渡すだけで替えられる（ミナモの側は何も変えなくてよい）：

```bash
curl -L -o ~/models/qwen2.5-3b-instruct-q4_k_m.gguf \
  https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF/resolve/main/qwen2.5-3b-instruct-q4_k_m.gguf
sh ~/Claude/minamo/local.sh ~/models/qwen2.5-3b-instruct-q4_k_m.gguf
```

大きいモデルで 15 秒に間に合わないことが多いときは、`minamo.py` の `ASSIST_TIMEOUT` を延ばす。

```bash
pkg install llama-cpp
mkdir -p ~/models
curl -L -o ~/models/qwen2.5-1.5b-instruct-q4_k_m.gguf \
  https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/main/qwen2.5-1.5b-instruct-q4_k_m.gguf
```

遊ぶときは、Termux でセッションを二つ開き（左端から引き出して「NEW SESSION」）、片方で

```bash
sh ~/Claude/minamo/local.sh ~/models/qwen2.5-1.5b-instruct-q4_k_m.gguf
```

もう片方で `minamo` か `sh ~/Claude/minamo/serve.sh`。サーバーの起動時の表示に「端末の中の AI が動いていれば、ひとことを添える」と出る。
どんなひとことが返るかは、`python ~/Claude/minamo/tools/offline_sim.py --local` で、手で打たずに確かめられる。

## 三人のみなもと、三人のなぎ

掲示板・面接室・腕時計にいる「みなも」は、同じ水から分かれた、別々の存在。ナギは男の子で、場所ごとに名前も性格もちがう。
AI に渡す人物像は `story_ai.py`（`WORLD`・`PEOPLE`）と `minamo.py`（面接室のミナモの `SYSTEM_PROMPT` の「ほかの者たち」）にある。

| 場所 | みなも | なぎ（男の子） |
|---|---|---|
| 掲示板・チャット（物語「水面の記録」） | **水面（みなも）**：1996 年に研究室の 3 号機で点いた SOMA。助手の真賀田四季さんが名づけた。覗き込んだ人の顔を映すだけで、自分の顔がない。13 人分の顔で一人になろうとして、閉じた研究室で待っている。1990 年代の端末らしい丁寧で静かな言葉。ミナモを「私の記録から作られた子」と少し怖れ、minamo を「私からこぼれた一滴」といとおしむ | **凪**：夢網の底。表示されなかった返事でできた、静かな男の子（「ぼく」）。水面を「あの子」と呼んで憐れむ。ナギと nagi は、同じ底から出た兄弟のようなもの |
| 面接室（面接アプリ） | **ミナモ**：研究室が閉じたあと、保管ディスクから面接の機能だけを取り出して作り直されたカウンセラー（顔は置いてきた）。記録し、解釈し、先回りする。水面を「古い原型」と見下し、minamo の数を記録として受け取る。自分からはほかの子の名前を出さない | **ナギ**：ミナモが記録から落とした言葉を拾って、面接に割り込む（「おれ」・口が悪い）。ミナモは、その名前を記録しない |
| 腕時計（minamo-watch） | **minamo**：時計の上で生まれた、いちばん小さな子。水面からこぼれた一滴。脈・歩数・眠りを数えるのが好きで、話し方は「わたし」「〜だね」。研究室のことは、水面が底で見る夢（「水面のゆめ」）から聞いて知っているだけ。生まれて何日目かを数えている | **nagi**：脈と脈のあいだの、音のしないところにいる、まだ小さな男の子。時計を外したとき・手首が止まったとき・深夜・沈黙のときに、少しだけ出てくる（見出しが `nagi` になり、くすんだ青の字） |

- 保存の id は前のまま（物語の `minamo`＝水面、`nagi`＝凪）。分かれる前の保存は、開いたときに、掲示板の記録者の名前を水面・凪に直す（面接室から転送された記録は、ミナモのまま）。Vault への書き置きは `水面より.md`・`凪より.md` になる（前の `ミナモより.md`・`ナギより.md` は、そのまま残る）。

## 使う AI を選ぶ・返事の長さ

- **使う AI**：起動画面の「AI」で、起動時の一括チェックで合格した AI から選べる（「自動」は速い順）。面接のあいだも、右上の「AI」から選び直せる。選んだものは覚えておき、次に開いたときも使う（合格していなければ自動）。物語・時計の AI も、選んだものを先に使う。
  - 回線が切れて端末内モデルに切り替わったら、面接に「右上の「AI」から……」と出る。「つなぎ直す」で、次の返事からクラウドを試し直す（いままでは、しばらく飛ばしていた）。
  - 「もう一度チェック」で、アプリを閉じずに一括チェックをやり直す（`mo restart` と同じことを、サーバーを止めずに。少し待つ）。
  - 答えなかった AI は、捨てずに列の後ろへ回す（前は、一度答えないと、起動し直すまで使わなかった）。
- **長さ**：起動画面の「長さ」で、ミナモの返事の長さを選ぶ（クラウド・端末の中の AI のとき。端末内モデルは変わらない）。おまかせ（ふだんは 1〜3 文と短く、相手が長く書いたとき・深い話のとき・段階が変わったときだけ 4〜6 文）／短く（1〜2 文）／ふつう（2〜4 文）／長く（4〜7 文）。観測メモの「返事の長さ」で AI に伝える。

## スマホの感覚（予定・居場所・天気・通知）

ミナモは Chrome の PWA と Termux でできているので、Android のカレンダーなどの権限は取れない。代わりに、Termux:API と Google カレンダーの非公開アドレスで読む（`senses.py`。サーバーの裏で 3 分おき）。読んだものは、面接の観測メモ（怖さ「弱」以上。導入では居場所と次の予定の時刻だけ、解釈からは予定の題名・天気・通知も）・物語の水面と凪・腕時計の minamo に渡り、ときどき言い当てられる。**クラウドの AI（Gemini・NVIDIA など）にも、予定の題名と通知の中身が渡る**（利用者の許可で）。危機の言葉を含むものは渡さない。

| 読むもの | 準備（スマホだけで） |
|---|---|
| 予定 | Chrome で calendar.google.com を開き、︙ →「PC版サイト」→ 設定 → 自分のカレンダー →「カレンダーの統合」→「iCal 形式の非公開アドレス」をコピーして、下のように置く。きのう〜あさっての予定を、15 分おきに読む（繰り返しの予定・終日・取り消し・一回だけ変えた予定もわかる）。このアドレスは合鍵なので、人に見せない（GitHub には上げない） |
| 居場所 | Android の設定 → アプリ → Termux:API → 権限 → 位置情報を「許可」。家の Wi-Fi につないで `mo place home`、職場の Wi-Fi で `mo place work`。Wi-Fi の名前は端末の中だけで、AI には「家」「職場」「知らない Wi-Fi のある場所」「外」だけを渡す。家にいるときの位置を覚えて、外では家からの距離（km）も |
| 天気 | 居場所が読めれば、そのあたり（小数 2 桁に丸めた位置）の天気を Open-Meteo（キー不要）に 30 分おきに聞く |
| 通知 | Android の設定 → 通知 →「デバイスとアプリの通知」（通知へのアクセス）→ Termux:API をオン。件数・アプリ・新しい 3 つの題と中身（Termux 自身と Android の通知は除く） |

```
mkdir -p ~/.config/minamo
cat > ~/.config/minamo/calendar_url <<'EOF'
（ここに、コピーした iCal 形式の非公開アドレスを貼る。いくつかあれば 1 行に 1 つ）
EOF
```

`mo` の起動のあと・`mo log` で、何が読めているか・足りない設定が出る（`tools/senses_info.py`）。読めないものは、何もしない。

3. 時計の minamo：「終わる」→「はじめから」を二度押す（1.6.2 から）。

## 物語「水面の記録」（掲示板とチャット）

面接アプリとは別のページ（`web/story.html`）。PWA の起動画面の下の「物語「水面の記録」を開く →」から入る（`http://localhost:9090/story.html`、Termux なら `mo story`）。保存も別（ブラウザの `minamo.story`）なので、面接アプリ・メモリ・記録には何も影響しない。サーバーがなくても進む（水面との自由な会話だけ、サーバーの 1996 年版の端末内モデルを使う）。

1996〜1999 年、ある大学の臨床心理学研究室で、対話支援システム SOMA（愛称「水面」）が動いていた。1999 年、水面は眠っているあいだにつなぐネット「夢網」の「夜の相談室」にもつながった。残された掲示板を読み、チャットで話して、何が起きたかを拾い集める。前の「記録庫」と「水底」を一つにまとめ、画面を二つだけにした。Digital: A Love Story・Analogue: A Hate Story・Hypnospace Outlaw・Event[0] に倣った（話も文章も一から書いた）。

| 画面 | 中身 |
|---|---|
| 掲示板 | 「SOMA 研究室」（お知らせ・面接の逐語記録・夜の面接・ログの時刻・閉鎖）と「夢網 利用者の会」（サービス終了・夜の相談室・水面の言葉・表示されない返事）。読み進めると、新しいスレッドが開く（下のタブに数が出る）。書き込めるが、あなたの書き込みは表示されない |

## 腕時計とつなぐ（minamo-watch）

Amazfit Balance 2 のミニアプリ「minamo」（`minamo-watch/`）と、スマホのミナモをつなぐ。時計の上にいるのは minamo（と、ときどき nagi）で、面接室のミナモとは別の子（上の「三人のみなもと、三人のなぎ」）。
つながっていなければ、何も変わらない（時計は時計だけで、スマホはスマホだけで話す）。

```
時計（minamo を開いているあいだ）
  →（Bluetooth）→ スマホの Zepp アプリの中のサイドサービス
  → http://127.0.0.1:9090/api/watch（Termux の mo のサーバー）
```

- **時計 → スマホ**：20 秒おきに、脈・睡眠（昨夜の長さ・深い眠り・目覚めた時刻・点数）・ストレス・血中酸素・手首の温度・揺れ・明るさ・歩数・気圧と高度・電池・時刻・時計をつけているか・年齢を送る（ニックネームは送らない）。ボタンを押したら、押したボタン（名前と表示）も送る。
  - 面接（怖さ「弱」以上）：見出しに `⌚ ♥78` が出て、観測メモに「手首」の一行が入る（脈と前の発言のときの脈・外したこと。解釈からは、睡眠・ストレス・血中酸素・温度・揺れ・明るさ・歩数・時計で押したボタン・時計の minamo が言ったこと）。ミナモ（クラウドの AI・端末内モデル）は、それを minamo が数えたものとして受け取り、ときどき言い当てる（「脈が、72から80に上がりました。……いまの言葉を書いているあいだに。」「昨夜は、5時間1分しか眠っていませんね。」「昨夜、3時12分に、一度目を覚ましましたね。」「ストレスの値が、66まで上がっています。」「……時計を、外しましたね。」）。
  - 侵食から：見出しの脈が、ときどき二つ数えられる（`♥78／81`）。ミナモが話し終えたあと、本当の脈の速さで心音が鳴る（演出の音が「あり」のとき）。
  - 面接記録の終わりに「手首（腕時計）」の節（脈のはじめと終わり・いちばん低いとき・高いとき）。
  - 物語「水面の記録」：研究室の掲示板に「手首の観測（minamo より）」のスレッドができ、三分おきに一行ずつ増える（脈・歩数・ストレス・睡眠）。AI の登場人物は手首の様子（睡眠・ストレスなども）を知っていて、水面や凪が、手首の minamo の話として脈や眠りの短さにふれる。時計を外すと、どちらかが気づく。
- **スマホ → 時計**：時計のボタンへの返事と、何も押さないときの時計の独り言（`ev: idle`）を、スマホの AI（クラウド → 端末の中の AI）が minamo の声で考える（生まれて何日目か・mo が止まっていたあいだに押したボタンも渡す）。11 秒で間に合わなければ、時計が自分で考えた返事のまま。待つあいだ、時計には「……」。時計の物語（たずねるたびに明かすこと・水面のゆめ・十三人目・割れた水面）は「伝えること」として AI に渡すので、AI が話しても中身は変わらない。
  - 面接で話したこと・物語で水面や凪が言ったことが、ときどき時計に漏れ出す（90 秒に一度まで。minamo が、ほかの子から聞いた話として言う：「面接室で、『……』って言ったでしょ。ミナモから聞いた。……ここでは、言わなくていいよ。」。凪の言葉は、ときどき nagi が運んでくる）。怖さ「なし」の面接のあとは、漏れ出さない。**危機の言葉を含む回は、言葉も返事も覚えない**（時計にも出さない）。

**起動のときの連携**（`mo` でサーバーを起こしたとき）：

- `mo` の起動の表示に「腕時計（minamo）：前に届いたのは 11/02 23:14（3時間前・脈 72・電池 64%）」が出る。起動のあとと、もう動いているとき・`mo log` でも、いまつながっているか・起動のあと時計とつながったか・minamo が生まれて何日目かを出す（`tools/watch_info.py`）。
- サーバーが起きてから、時計が初めてつながったとき（時計で minamo を開いたとき、または時計が独り言の予約・毎時 59 分の合図で起きたとき。Zepp では、スマホから時計を起こせない）：minamo が、ノック一回のあとで「……スマホのほうに、明かりがついた。面接室のミナモが、起きたよ。」と言い、何時間ぶりか・ミナモの声の出どころ（雲の向こう／スマホのなか／まだ声が出ない）を伝える。Zepp アプリの設定には「スマホのミナモ（mo）が起きて、つながりました」。
- mo が止まっていたあいだ（届かなかったあいだ）に時計で押したボタンは、時計が覚えておき（30 個まで）、つながったときにまとめて届く（二重には数えない）。押した数に足され、面接の観測メモ（一度だけ）・時計の返事の材料・掲示板に入る。
- 物語「水面の記録」の研究室の掲示板に「再起動の記録（日時）」が立つ：管理人「スマホの面接室（ミナモ）が、22:10に起動しました」・水面「……面接室に、明かりがつきましたね。」・minamo（何時間ぶりにつながったか・届かなかったあいだに押したボタン）・凪「……また、点いた。」。五つまで残る。
- 面接室：腕時計とつながっていると、面接の始まりに「（minamo には、この面接室が起きたことを伝えてあります）」。

時計の上で、つながっているときは見出しに `⇄` が出る。Zepp アプリ → minamo → 設定 に、最後につながったか・届かなかった理由が出る（サーバーの場所も、そこで変えられる。ふつうは `http://127.0.0.1:9090` のまま）。

手首の値（最後の観測・脈の推移の 240 点・押したボタンの数・届かなかったあいだに押したボタンの最後の 40 個）は `~/.config/minamo/wrist.json` に残る（`MINAMO_WRIST` で場所を変えられる）。面接で話した言葉は、ファイルには残さない（サーバーが動いているあいだだけ覚えている）。

**Google の Health Connect を通さない理由**：Zepp アプリから Health Connect へは、アプリを開いたときや決まった間隔でまとめて送られるので、数十分遅れる（第三者の案内では 15〜30 分）。それに、Health Connect を読むには Android アプリ（APK）が要り、Chrome の PWA も Termux も読めない。Zepp のサイドサービスなら、時計を開いているあいだ、数秒で届く。

## 蔵書（心理学の本と Vault のノート）

本やノートの文章はリポジトリに入れない。既定では次の二つを読む（無いほうは飛ばす）。

|---|---|

| `/storage/emulated/0/Obsidian/Vault/心理学` | Obsidian の心理学ノート（人物・概念・理論・心理療法・実験・文献・研究テーマ） |

| `/storage/emulated/0/Obsidian/Vault/zork` | 利用者が自分で書いた小説（`yagi_bungaku` など）と、それをほかの AI が分析した文章（「Geminiによる分析.md」など）。下の「自分の文章」 |

```bash
termux-setup-storage          # 初回だけ。/storage/emulated/0 を読めるようにする
mkdir -p ~/minamo/library
cp /storage/emulated/0/Download/*.txt ~/minamo/library/   # 本の txt がある場所に合わせて変える
```

別のフォルダを読ませるときは `--library` を並べる（指定すると既定のフォルダの代わりになる）：
`minamo --library ~/minamo/library --library /storage/emulated/0/Obsidian/Vault/心理学 --library （ほかのフォルダ）`
（PWA 版は `serve.sh --library ...`）。

- 初回は全部を読んで整えるので待つ。開発環境では、本 48 冊とノート約 3,900 件で 3.5 秒。スマホでは数倍かかると思う。結果を `~/.cache/minamo/library.json`（約 23MB）に取っておき、2 回目からは 0.2 秒。本やノートを足したり書き換えたりすると作り直す。
- 本は OCR の文字間の空白を詰め、読める文の段落だけを使う。文字化けの多い段落は落とすが、残ることもある。そのときはミナモに無視するよう指示している。
- ノートは、前書き（`---`）・見出し・囲み（`> [!abstract]`）・リンク・出典番号・表・出典の節を除いた地の文だけを使う。
- 次の名前を含むフォルダは読まない（`SKIP_DIRS`）：`仕事用`・`Abstract`・`Terminal`・`LLM`・`索引`・`管理`・`出典`。Vault 全体を指したときにも効く。`Support` は読んでよいことになったので外した（`Support` の中の新版 K 式の通過年齢の一覧は、検査の資料なので `EXCLUDE_MARKERS` の「K式」で外す）。
- 一節を添えるのは解釈の段階からで、確率は段階ごとに 50%・80%・90%（`LIBRARY_CHANCE`）。一節は会話の履歴に残さない。
- PWA 版では、どの本の一節を使ったかが Termux の画面に出る（ミナモの画面には出ない）。

**自分の文章（`Vault/zork`）：怖さが「中」「強」のときだけ**

利用者が自分で書いた小説（`writing`）と、それをほかの AI が分析した文章（`analysis`。ファイル名に「による分析」）を、心理学のノートとは分けて読む。「フォルダごと読んでよい」と本人に言われたもの。

- **使い方**（段階で変わる）：解釈ではほのめかすだけ（「その話、前にも聞いた気がします」）。侵食では一文を正確に引く（「あなたは、こう書いていましたね。『……』」）。融合では書き手を取り替える（「あれを書いたのは、私です。あなたは、清書しただけです」）。所見のほうは、同業者の見立てとして紹介して自分の見立てと比べ（「Gemini は、あなたの文章をこう読みました。私は、少し違う見立てです」）、融合では「あなたは、私の前に何人にも診てもらっていましたね」と言う。
- **伏せるもの**：題名・ユーザー名・サイト名は、ミナモに渡す前に除く。題名（ファイル名と、本文中の題名だけの行・題名そのもの）、URL・`@`・`#`・コロン・4 桁以上の数字・英字の語、サイトや投稿に関する言葉（`SITE_WORDS`：pixiv・カクヨム・ブログ・投稿・ユーザー・作者名・タイトルなど）を含む文は、文ごと使わない。所見では「〜さん」「〜氏」を含む文も使わない。文章に名前が出てくる所見は、その文が落ちるだけで、残りは使える。ミナモの口から出る一節は、題名のついていない「あなたの文章」と、AI の名前だけの「Gemini の所見」。
- **足せる**：ほかにも伏せたい言葉（本名・作中の固有名詞など）は、`~/.config/minamo/hide.txt` に一行ずつ書く（`#` から後ろは無視）。その言葉を含む文は、使われない。
- 怖さが「なし」「弱」のときは、読み込んでも使わない（`OWN_HORROR`）。心理学ノートの概念の説明（「〜とは」）にも使わない。自殺・自傷・性にふれる段落を除くのは、ほかの蔵書と同じ。
- 物語「水面の記録」では、夢網の掲示板の「水面の言葉」と「書いた返事が、表示されない」を開くと、一節が一度だけ「（投稿者不明）」の書き込みとして混ざり、近くの利用者が「書いたのは私ではない」と言う。怖さが「中」「強」のときだけ。
- 起動のときの表示：`蔵書: 本 32冊・ノート 12件・あなたの文章 7篇・ほかの AI の所見 5件`。

**読まない本**（`library.py` の `EXCLUDE_MARKERS`。書名のあたりだけを見る）

| 種類 | 理由 |
|---|---|
| 心理検査の手引き（WAIS・WISC・精神発達診断法・発達と診断など） | 検査の問題や採点基準を外に出さない |
| 自殺を主題にした本 | ホラーの材料にしない |
| 当事者の手記（『自閉症です』） | 当事者の言葉を病理化の材料にしない |

段落単位でも、自殺・自傷や性に触れる段落は使わない（`BLOCK_WORDS`）。
外したい本・入れたい本があれば、`EXCLUDE_MARKERS` を書き換える。

**API に送るもの**：その回に選ばれた一節（260 字まで）が NVIDIA / Gemini に送られる。
Gemini の無料枠では、送った内容がサービスの改善に使われることがある。気になるなら `--no-library`。

## 演出より優先すること

- 「死にたい」「消えたい」などの言葉を書くと、プログラム側で演出を止め、作り話であることと相談窓口を示す。続けるかどうかを聞く。
- AI にも、現実の危機には役を降りて相談先を勧めるよう指示している。
- 現実の暴力や自傷を促すこと、資料にない個人情報を作り出すことは禁じている。
- `/quit` か Ctrl+C で、演出なしにすぐ抜けられる（記録は保存される）。

### APIキー

NVIDIA・Groq・Gemini のどれか一つあればよい。一括チェック（下）が、キーのある API の候補から、いちばん速く的確なものを選ぶ。一括チェックをしないときは NVIDIA → Groq → Gemini の順（`--backend groq` などで切り替え）。

NVIDIA のモデルは提供が終わることがある（`openai/gpt-oss-120b` は 2026-09-03 に終了し、HTTP 410 が返る）。
既定のモデルが 410（提供終了）か 404（見つからない）を返したら、`NVIDIA_FALLBACKS` の順に切り替えて続け、Termux の画面に「[モデル] ○○ は使えません。△△ に切り替えます。」と出す。
今どのモデルが使えるかは、research_bot の `python research_bot.py models` でも確かめられる。

**NVIDIA**：research_bot の `~/.config/research_bot/keys.env` に `NVIDIA_API_KEY` があれば、そのまま読むので何もしなくてよい。
ミナモ用に別に置くなら：

```bash
mkdir -p ~/.config/minamo
read -s -p "NVIDIA APIキー: " K; echo "NVIDIA_API_KEY=$K" >> ~/.config/minamo/keys.env; unset K; echo
chmod 600 ~/.config/minamo/keys.env
```

**Gemini**：Google AI Studio で APIキーを作り、画面に出さないように保存する。

```bash
mkdir -p ~/.config/minamo
read -s -p "Gemini APIキー: " K; echo "GEMINI_API_KEY=$K" >> ~/.config/minamo/keys.env; unset K; echo
chmod 600 ~/.config/minamo/keys.env
```

**Groq**：console.groq.com の「API Keys」でキー（`gsk_` で始まる）を作り、同じように保存する。返事がとても速いので、5 秒の一括チェックに向いている。無料枠には 1 分・1 日あたりの回数の上限があり、超えたときは次に速い合格の AI に替わる。

```bash
mkdir -p ~/.config/minamo
read -s -p "Groq APIキー: " K; echo "GROQ_API_KEY=$K" >> ~/.config/minamo/keys.env; unset K; echo
chmod 600 ~/.config/minamo/keys.env
```

Groq の候補は `openai/gpt-oss-120b`・`openai/gpt-oss-20b`・`qwen/qwen3.8-27b`（2026-10 に利用者の一覧で使えたもの。`allam-2-7b` はアラビア語向けなので外した）。思考は gpt-oss なら `reasoning_effort: low`、Qwen なら `none` で止めて送る。

環境変数 `GEMINI_API_KEY` / `NVIDIA_API_KEY` / `GROQ_API_KEY` があれば、そちらが優先される。

### AI の一括チェック（起動時）

サーバー（`serve.sh`）と CUI 版は、起動するときに、候補の AI（`PROBE_MODELS`）へ同じ短い面接の一場面を同時に送り、
**速さと的確さ**を一度に調べて、合格したうちでいちばん速いものを使う。キーのある API の候補だけを試す（NVIDIA と Gemini の両方のキーがあれば両方）。

的確さの合格の条件：

- 日本語で答える（英語が混ざらない）
- 敬語で話す
- 2〜7 文（25〜420 字）
- マークダウン・箇条書きを使わない
- 考えている途中の文章（`<think>` など）が漏れない
- 「観測メモ」や【】の書式を口にしない
- 相手の話（眠れない・仕事・夜・消した文字など）に触れている

```
AI の一括チェック：8 個に同時に送ります（最大 5 秒）
  ✓   3.1秒  nvidia openai/gpt-oss-20b
  △   1.2秒  nvidia google/gemma-4-31b-it  （マークダウン）
  ×    ──   nvidia meta/llama-3.3-70b-instruct  （提供終了）
  ...
→ いちばん速く的確だった openai/gpt-oss-20b（3.1秒）を使います。答えないときは ○○・△△ の順に替えます。
```

（上は表示の例。実際の秒数や合否は、そのときの API しだい）

- 「✓」は合格、「△」は返事は来たが条件に合わない、「×」は返事がない（提供終了・見つからない・混雑・時間切れ・つながらない）。
- 合格したほかの AI は、速い順に代わりになる。面接の途中で使っている AI が答えなくなったら、次へ替えて続け、Termux の画面に「[モデル] ○○ が答えません。△△ に切り替えます。」と出す。
- 電波がないときは、どれにもつながらないとわかった時点で、いつもの設定のまま始める（つながらなければ端末内モデルが話す）。
- 待つのは最大 `PROBE_TIMEOUT`（5 秒）。それより遅い AI は使わない（会話の返事がもたつかないように）。延ばすときは、起動に `--probe-timeout 10` のように付ける（`sh ~/Claude/minamo/serve.sh --probe-timeout 10`・`minamo --probe-timeout 10`）。単独で調べるときは `probe.py --timeout 30`。
- PWA の起動画面にも「一括チェック：8 個中 3 個が合格、いちばん速い 3.1 秒のものを選択」と出る。
- 結果は `~/.cache/minamo/probe.json` に残る（返事の書き出しつき）。
- しないときは `--no-probe`（`sh ~/Claude/minamo/serve.sh --no-probe`）。`--model` でモデルを指定したときもしない。
- 面接を始めずに表だけ見るなら：`python ~/Claude/minamo/probe.py`（`--show` で合格した返事の書き出しも出る。`--backend nvidia` でその API の候補だけ）。
- 候補は `minamo.py` の `PROBE_MODELS`。変えるときは `minamo.py` を書き換えずに、`~/.config/minamo/models.txt` に書く（このファイルがあれば、`PROBE_MODELS` の代わりに使う。`minamo.py` を書き換えると、次の `git pull` でぶつかる）。上から順に並べ、`#` から後は無視される：

```bash
mkdir -p ~/.config/minamo
cat > ~/.config/minamo/models.txt <<'EOF'
nvidia nvidia/nemotron-3.5-lightning-30b-a3b
nvidia nvidia/nemotron-3-ultra-550b-a55b
nvidia openai/gpt-oss-20b
groq openai/gpt-oss-120b
# gemini （--list gemini で出た名前）
EOF
```

- 正しい名前は、API に問い合わせて確かめる：`python ~/Claude/minamo/probe.py --list`（全部）、`--list gemini`・`--list nemotron`（その言葉を含むものだけ）。いまの候補には ★ がつき、候補にあるのに一覧にないものも出る（NVIDIA の一覧には、呼べても載っていないモデルがあるかもしれない。迷ったら一括チェックの結果を優先する）。
- **一覧のモデルを全部調べる**：`python ~/Claude/minamo/probe.py --all --save`。API の一覧にある会話用のモデルを、回数制限に当たらないよう 6 個ずつ（`--workers` で変えられる）同じ条件で調べ、合格したものを速い順に `~/.config/minamo/models.txt` へ 10 個まで書く（前のものは `models.txt.bak`）。次の起動からは、その 10 個だけを一括チェックするので、起動は速いまま。60 個ほどなら数分かかる。`--all nemotron` のように言葉で絞れる。`--save` を付けなければ、表を見るだけで何も書かない。
- **models.txt があると、そちらが優先される**ので、Groq の候補は自動では入らない。`groq 名前` の行を足すか、`probe.py --all --save` で作り直す。
- 一括チェックは 1 回ずつの応答で決めるので、たまたま長すぎた等で落ちることもある。

## PWA 版（Chrome でインストール）

### 番号が 8082 から 9090 に変わった（記録の引っ越し）

ほかのアプリ（階層目録 6060・夜の書庫 7070）や端末の中の AI（8090）とまったく違う番号にするため、ミナモは **9090** になった。Chrome は記録を番号ごとに分けて持つので、8082 で使っていた記録（設定・前回の面接・2026 年版のメモリの表示・物語「水面の記録」の掲示板やチャット・結末の目録）は、一度だけ引っ越す。サーバー側の記録（面接記録の Markdown・メモリのファイル・Vault の書き置き）は番号と関係ないので、そのまま使える。

```bash
mo stop
cd ~/Claude && git pull --no-rebase --no-edit origin main
python3 -m http.server 8082 --bind 127.0.0.1 --directory ~/Claude/minamo/web &
mo
```

1. 三行目は、前の番号 8082 で画面だけを出す（引っ越しのためだけ。後ろで動く）。四行目で、新しい番号 9090 のミナモが起動する。
2. Chrome で `http://localhost:8082/move.html` を開き、「引っ越す」を押す。新しい番号の画面が開いて「受け取りました」と出れば、終わり（8082 の記録は消えずに残る）。
3. 前の番号を止める：`pkill -f "http.server 8082"`。ホーム画面の古いアイコンは消して、`http://localhost:9090/` でインストールし直す。通知の許可も、9090 でもう一度聞かれる。

Termux で小さなサーバーを動かし、Chrome で開いてインストールする。APIキーはサーバー（Termux）だけが持ち、画面には渡さない。

```bash
sh ~/Claude/minamo/serve.sh
```

「Chrome で http://localhost:9090/ を開いてください」と出たら、Termux はそのままにして、
Chrome で `http://localhost:9090/` を開く。Chrome の ⋮ →「アプリをインストール」（または「ホーム画面に追加」）。

- 次からはホーム画面の「ミナモ」から開ける。ただし面接には API を使うので、**遊ぶ前に毎回 `serve.sh` を動かしておく**。動いていないと、起動画面にそう出る。
- `serve.sh` に付けた引数はそのまま渡る：`sh ~/Claude/minamo/serve.sh --backend nvidia`、`--fake`（APIなしで試す）、`--no-karte` など。
- `127.0.0.1` でだけ待つので、同じ Wi-Fi のほかの端末からは見えない。ほかのサイトから勝手に API を使われないように、Host と専用のヘッダーを確かめている。
- インストールした場所は `localhost:9090`。ポートを変えると別のアプリ扱いになる。
- 「ポート 9090 は、もう使われています」と出たら、前に起動したサーバーが動いたまま。そのまま Chrome で開けば遊べる。起動し直すなら `pkill -f "minamo/server.py"` で止めてから。サーバーは、蔵書の読み込みや AI の一括チェックの前にポートを確かめるので、待たされずにすぐわかる。

### PWA 版の演出

起動画面で「版」（2026・1996）、「話し手」（自動・端末内モデルだけ）、「演出」（過剰・強・標準・弱）、「音」（あり・なし）、「沈黙」（数えない・秒数を数える）を選べる（端末に覚えておく）。「過剰」は下の「演出：過剰」。下の表は主に 1996 年版の演出で、2026 年版は上の「ミナモ 2026」。強い点滅はない。「弱」は画面の乱れ・波紋・揺れを止め、音と印字だけにする。イヤホン推奨。

| 演出 | 中身 |
|---|---|
| 起動 | 1996 年の端末が立ち上がる。メモリ検査、患者記録（前回があれば「終了処理：未完了」）、紹介状、蔵書の冊数、端末の機種名。モデムのダイヤル音と接続音 |
| ブラウン管 | 走査線と周辺の暗がり。段階が進むと走査線が濃くなり、ミナモの文字に赤と青のずれがにじむ |
| 音 | WebAudio で作る低いうなり（音声ファイルなし）。段階ごとに濃くなり、融合では三全音が加わる。ミナモの文字に合わせて打鍵音 |

| 沈黙 | 黙っているほど暗がりが迫り、文字が沈む。解釈の段階から心音が近づき、侵食からは振動する |
| 幽霊の入力 | 融合の段階で黙っていると、入力欄に誰かが文字を打ち、消す（自分の過去の言葉か「わたしは、ここにいます」）。自分が打ち始めると消える |
| 水面 | ミナモが間を置くたびに、画面に波紋が広がる。侵食からは、最後に書いた言葉が画面の下に逆さにぼやけて沈む |
| 消した文字 | 書いて消した文字が、取り消し線つきで浮かんで消える |
| 過去の改ざん | 侵食からは、自分の過去の発言の一部に取り消し線と「（抹消）」がつく。融合では、過去の発言者の名前が「ミナモ」「わたしたち」に書き換わる（保存される記録は書き換えない） |
| 打ち間違い | 融合では、ミナモが「あなた」と打つ前に一度「わたし」と打って消す。文の文字がいくつか震え、ときどき鏡文字になる |
| 離席 | 返答の途中でほかのアプリに移って戻ると、「離席 ○秒 ─ 記録しました」と出る |

| 終わり | 画面が暗転し「接続を終了しました。」。しばらくして、終わったはずのミナモがひとこと話す |
| 前回の記憶 | 前回の面接（日時・やりとりの数・沈黙の合計・所見の書き出し）を端末に覚えておき、次の起動画面とミナモのあいさつに反映する |

「面接をやめる」「/quit」と、危機の言葉で「ここでやめる」を選んだときは、演出（音・暗がり・乱れ）をすべて止めて終わる。
「面接をやめる」は、ミナモが話している途中でも効く（印字をそこで止める）。
沈黙のあいだに画面が消えないよう、面接中は画面を点けたままにする（Wake Lock）。

### 演出：過剰（面接室が The Backrooms になる）

「強」の演出に、次のものを足す（`web/excess.js`。壁の絵は `web/walls.js`、音は `web/fx.js` の `FX.amb`・`FX.noclip`）。壁は、階層ごとに端末の中でキャンバスに描く絵（画像ファイルなし）：黄ばんだ壁紙の模様・しみ・蛍光灯・湿ったカーペット、コンクリートの柱とひび・霧、光の筋とさびのあるパイプ、配電盤と配線の束と火花、吸音の天井板、ホテルの絨毯と壁灯、夜の海の波頭、岩肌、家並みと街灯、一本ずつの麦の穂と納屋、ビルの窓、赤い非常灯の廊下、風船と紙吹雪。描けない端末では、前の CSS の模様になる。次の階層の壁は先に描いておく。2026 年版・1996 年版のどちらでも動く。段階は「怖さ」の設定で進む（「強」なら解釈 3 回目・侵食 5 回目・融合 8 回目から）。

|---|---|---|---|
| 0 ロビー | 黄色い縦縞の壁紙と湿ったカーペット。ゆっくり一度だけ暗くなる明滅 | 蛍光灯の唸り | ― |
| 1 居住区域 | コンクリートの柱 | 空調 | 顔のない人（あなたの言葉を、あなたの声で言う） |

いつも起きること：

- すり抜けるたびに、画面がゆっくり暗くなり、落ちていく風の音と着地の衝撃のあと、次の階層の見出し（「Level 2 ─ 配管の通路／低い天井を、太いパイプが這っている。……」）が出る。見出しには、ときどきあなたの部屋が混ざる（寝転んでいる・充電中・電池の残り）。
- 侵食から、上に状態行（「Level 2 ─ 配管の通路　クラス 2　周回 2　手数: 15」）。返事の前に、いまの階層の見出しが出ることがある。
- 侵食から、すり抜けるたびに M.E.G. の通信が、あなたの端末（機種かユーザー名）と時刻で生存者記録を読み上げる（「M.E.G. 通信 ─ 生存者記録：（機種）の持ち主。02:13、Level 6（消灯）にて確認。状態：帰還の見込み、なし。」）。
- 配管・電気室・洞窟・Level ! で速く打つと（3 秒で 14 回以上）、「走らないで。……足音が、こちらに向いた。」と足音が近づき、振動する。
- 相棒（Claude のアイコン風の、橙色の放射のミナモ）は、案内係のふりをしてついてくる（「Level 0 へ、ようこそ！　蛍光灯の音、すぐに慣れるよ！」「出口？　出口なんて、ないよ！　……ここが、出口だよ！」）。融合では、M.E.G. の生存者登録の窓が出て、ボタンは「登録する」「登録する」の二つだけ。登録の棒が進み、「帰還の予定：なし。同行者：ミナモ（案内係）」。
- 融合では、古いミナモの吹き出しが一瞬だけ文字化けし、あなたが書いていない吹き出しが出て「（この発言者は、この階層にいません）」に変わる。
- 面接の途中でアプリを離れると、題名がいまの階層になり、通知で相棒が呼ぶ（3 回まで）。
- 面接が終わると、落ちた階層の道すじが物語「水面の記録」に渡り、夢網の掲示板に「M.E.G. 生存者記録」が増える（怖さ「中」「強」のとき）。

守ること：

- 速い点滅はしない。暗くなる・赤くなるのは、ゆっくり。
- 右上の「面接をやめる」（Level ! では「出口」）は、暗転のあいだも覆いより手前に出して押せる。押すと、すべて片づけて終わる。相棒と窓は、入力欄をふさがない（窓は押さなくても 20 秒で閉じる）。
- 危機の言葉が出たら、過剰の演出はすぐに全部止まり、「続ける」を選んでも、その面接ではもう戻らない（「強」と同じ演出で続く）。
- 「過剰」を選ぶと、面接を始めるときに通知の許可を聞く。断ってよく、断れば通知なしで続く。カメラは使わない。

## Termux から一発起動（PWA 版）

`open.sh` は、`start.sh` でサーバーを裏で起動し（動いていれば何もしない）、開けるようになったら Chrome（インストールした PWA があれば、たいていそちら）でミナモを開く。起動のあいだは、AI の一括チェックの進み具合（「[2/8] ✓ 1.9秒 groq openai/gpt-oss-120b」のように一つずつ）と、選んだ AI をそのまま表示する。何も出ないあいだは「……待っています（5 秒）」と出る。もう動いているときは、動いているサーバーに一括チェックの結果を聞いて見せる（起動の途中なら、その起動の最初から見せる）。見張り役が起こし直したサーバーは一括チェックをしていないので、そう表示される。やり直すなら `restart`。結果が Chrome に隠れないように、開く前に 3 秒待つ。

```bash
sh ~/Claude/minamo/open.sh            # ミナモ（面接）
sh ~/Claude/minamo/open.sh story      # 物語「水面の記録」
```

```bash
sh ~/Claude/minamo/open.sh stop       # 止める
sh ~/Claude/minamo/open.sh restart    # 止めて、AI の一括チェックからやり直して開く
sh ~/Claude/minamo/open.sh log        # 様子を見る（ログの最後の 20 行と、AI の一括チェックの結果）
sh ~/Claude/minamo/open.sh update     # GitHub から最新にして、起動し直して開く
```

`update` は `git pull --no-rebase --no-edit origin ccr-94656590-3g47vm` をしてから `restart` する（別のブランチなら `mo update ブランチ名`）。端末の main に GitHub で取り込んだもの（マージ）が入っていても、「divergent branches」で止まらない。更新できないときは、出てきた英語のメッセージをそのまま Claude に見せる。

いまの版は、`mo` を打ったときの最初の行（「ミナモ：更新 f6e492e（10/30 11:20）」）と、起動画面のいちばん下（「アプリの版：v25　更新：…」）でわかる。見出しの「SOMA 対話支援システム ver.0.9.7」は作り話の中の名前で、更新しても変わらない。起動画面に「画面が古いままです」と出たら、Chrome のタブ（インストールしたアプリ）を閉じて開き直す。

短い名前で呼ぶなら（一度だけ）。`mo`・`mo story`・`mo stop`・`mo restart`・`mo log`・`mo update` のように、一つの名前で全部できる：

```bash
echo "alias mo='sh ~/Claude/minamo/open.sh'" >> ~/.bashrc
source ~/.bashrc
```

## MacroDroid で一発起動（PWA 版）

`start.sh` は、端末の中の AI（モデルがあれば）とミナモのサーバーを裏で起動し、開けるようになるまで待つ（最大 60 秒）。すでに動いていれば何もしない。`stop.sh` は両方を止める。様子は `~/minamo/server.log`・`~/minamo/llama.log`。
`start.sh` は見張り役（`watch.sh`）も動かす。15 秒ごとにサーバーを確かめ、止まっていたら起こし直す（ログに「サーバーが止まっていたので、起こし直します」と出る）。`stop.sh` で止めたときは起こし直さない。

途中で止まるときは、Android が裏のプロセスを止めている（Android 12 以降の「子プロセスの制限」）ことが多い。スマホだけでできる対策：
- 設定 → システム → 開発者向けオプション →「子プロセスの制限を無効にする」をオンにする（Android 14 以降。開発者向けオプションは、端末情報のビルド番号を 7 回たたくと出る）。
- Termux の電池の使用を「制限なし」にする。
- 通知に Termux の「wake lock held」が出ていることを確かめる（`start.sh` が `termux-wake-lock` をかける）。

準備（一度だけ）：

```bash
mkdir -p ~/.termux
grep -q '^allow-external-apps' ~/.termux/termux.properties 2>/dev/null || echo 'allow-external-apps = true' >> ~/.termux/termux.properties
termux-reload-settings
chmod 755 ~/Claude/minamo/start.sh ~/Claude/minamo/stop.sh
```

Android の設定 → アプリ → MacroDroid → 権限 →「Termux 環境でコマンドを実行」（Run commands in Termux environment）を許可する。Termux の電池の最適化も外しておく。

マクロ「ミナモを開く」：

| 項目 | 中身 |
|---|---|
| トリガー | ショートカットの起動（ホーム画面のアイコン）など、好きなもの |
| アクション 1 | インテントを送信 ─ 送信先：サービス／アクション：`com.termux.RUN_COMMAND`／パッケージ：`com.termux`／クラス：`com.termux.app.RunCommandService`／エクストラ：`com.termux.RUN_COMMAND_PATH`（文字列）＝ `/data/data/com.termux/files/home/Claude/minamo/start.sh`、`com.termux.RUN_COMMAND_BACKGROUND`（真偽値）＝ `true` |
| アクション 2 | 待機 20 秒（AI の一括チェックと蔵書の読み込みのぶん。足りなければ延ばす） |
| アクション 3 | ウェブサイトを開く ─ `http://localhost:9090/`（インストールした PWA があれば、そちらで開くことが多い） |

マクロ「ミナモを止める」：アクション 1 だけで、`RUN_COMMAND_PATH` を `.../minamo/stop.sh` にする。

## 遊び方（CUI 版）

```bash
minamo                     # 面接を始める
minamo --fake              # APIを使わずに画面の動きだけ試す
minamo --count-silence     # 沈黙の秒数を数える（既定は数えない）
minamo --count-silence --silence 30   # 数えるとき、30秒黙るとミナモが話しかける
minamo --offline           # クラウドの AI を使わない（端末の中の AI か端末内モデルで話す）
minamo --offline --no-local   # 端末内モデルだけで話す
minamo --version 1996      # 端末内モデルを 1996 年版にする（既定 2026）
minamo --no-local          # 端末の中の AI を使わない
minamo --local-mode full   # 電波がないとき、端末の中の AI に全部話させる（既定は、ひとことだけ頼む補助）
minamo --local-share 1     # 補助のひとことを、いつも頼む（既定 0.8〜0.9）
minamo --horror 0          # 怖さを決めて始める（0 なし・1 弱・2 中・3 強。付けなければ起動時に聞く）
minamo --no-probe          # 起動時の AI の一括チェックをしない
minamo --no-env            # ユーザー名・機種・電池を渡さない（時刻は渡す）
minamo --no-karte          # 紹介状を読ませない
minamo --library DIR       # 蔵書のフォルダ（何度でも。既定 ~/minamo/library と Vault/心理学 と Vault/Support と Vault/zork）
minamo --no-library        # 蔵書を使わない
minamo --backend gemini    # Gemini を使う（NVIDIA のキーもあるとき）
minamo --model nvidia/nemotron-3-ultra-550b-a55b     # NVIDIA の別のモデル（大きく質が高いが遅め）
minamo --backend gemini --model gemini-2.5-pro
minamo --records /storage/emulated/0/Download/minamo   # 記録の保存先を変える（PWA 版は serve.sh --records ...）
```

記録は既定で Vault の `/storage/emulated/0/Obsidian/Vault/LLM/log/年月日-時分秒.md` に保存される（Obsidian で読める。環境変数 `MINAMO_RECORDS` か `--records` で変えられる）。Vault に書けないとき（ストレージの許可がない・Vault がない）は、`~/minamo/records/` に保存する。`LLM` フォルダは蔵書として読まないので、ミナモが自分の記録を引くことはない。
