# 膨大な量のテキスト

目を覚ますと、文字の中にいた。上も下も、右も左も、テキストだ。
誰も数えきれず、一生かけても一割も読めず、書いた人はみんな死んでいて、読みに来る人ももういない。それでもテキストは増えつづけている——その底へ、ランプ一つで降りていく、カオスで、絶望的で、ひとりきりのホラー・テキストアドベンチャー。

- ファイル：`boudai-text.html`（HTML 一枚。外から読みこむのは DotGothic16 フォントと、青空文庫の本文）、`make-local.py`（手もとの青空文庫から棚を作る。任意）
- 操作：「空欄」「野帳」と同じ（状態行・「命令を作る」・十字キー・よく使う6ボタン・≡ メニュー・自動保存）
- 文章：ゲームの地の文は書き下ろし。積もっている「頁」と、頁の向こうから返ってくる声は、青空文庫の本物の文章

## 「未読」の帯

画面の上に、ここに積もっているテキストの字数が「未読」として出る。

- 手もとの棚があれば、`make-local.py` が数えた Vault2 の青空文庫の本当の総字数から始まる。GitHub から取るときは、目録の冊数 × 3 万字の見積もり。
- 頁を読むと、読んだ字数だけ減る。
- 一秒ごとに増える（深い層ほど、長く遊ぶほど速い）。頁の雪崩が起きると、一気に何万字も増える。読むより、増えるほうが速い。
- 終わったときに、読んだ字数と、残った未読が出る。

## 本文の取り方

### 手もとの棚（Obsidian の Vault2 から）

スマホの `/storage/emulated/0/Obsidian/Vault2` にある青空文庫の全文から、ゲーム用の棚ファイル `boudai-local.js` を作れる。
これを `boudai-text.html` と同じフォルダに置くと、ゲームは GitHub に取りに行かず、手もとの本だけで遊ぶ（電波がいらない）。

Termux で次を貼りつけて実行する。

```sh
cat > ~/boudai-shelf.sh <<'EOF'
cd ~/Claude
git fetch origin ccr-e757ea96-4yc97j
git checkout ccr-e757ea96-4yc97j
git pull origin ccr-e757ea96-4yc97j
python boudai-text/make-local.py /storage/emulated/0/Obsidian/Vault2 /storage/emulated/0/Download
cp boudai-text/boudai-text.html /storage/emulated/0/Download/
EOF
sh ~/boudai-shelf.sh
```

- 読むのは `.txt`・`.md`・`.html`。青空文庫らしいもの（「底本：」「青空文庫」を含む、ルビ《》や注記［＃］がある）だけを使い、ふつうのメモは読まない。`.obsidian` などの隠しフォルダも読まない。
- 青空文庫のテキスト形式（題名・著者・記号の説明・本文・底本）、Markdown の前置き（`title:`・`author:`・`没年:` など）、青空文庫の XHTML に対応する。ルビ・注記・外字の説明は取りのぞく。
- 見つけた本ぜんぶの字数を数えて、「未読」の始まりにする。
- 棚に並べるのは 100 冊まで（怪談寄りの書き手が 7 割）。一冊から 250 文。もう一度走らせると、棚の本が入れかわる。
- 没年はファイルに書いてあればそれを使い、なければ主な書き手の没年の表から引く。どちらにもなければ「没年不明」。
- 終わると、見つけた本の数・総字数・多い書き手が表示される。0 冊なら、ファイルの形が想定と違う。

Tasker で開くときは、`boudai-local.js` も `/storage/emulated/0/Tasker/boudai-text/` にコピーする。

### GitHub の青空文庫から（手もとの棚がないとき）

スマホのブラウザが、青空文庫のリポジトリ（[aozorabunko/aozorabunko](https://github.com/aozorabunko/aozorabunko)）から直接読みにいく。

1. 目録：`index_pages/list_person_all_extended_utf8.zip`（作家別作品一覧の CSV）を取り、ブラウザの中で zip をほどく。著作権の切れた作品（作品著作権フラグ「なし」）だけを使う。目録は 30 日間、端末に残す。
2. 本：層を降りるたびに、目録から本を一冊（＋まぎれこむ本を一、二冊）選び、`cards/…/files/…html`（Shift_JIS の XHTML）を取る。ルビ・注記・外字の画像は取りのぞく。
3. 取ってきた本は 14 冊まで端末に残し、電波がないときはそれで遊ぶ。一冊もないときは、このゲームのために書いた白紙に近い頁で遊ぶ（そのことは画面に出る）。

どちらの取り方でも、怪談・幻想寄りの書き手（夢野久作・岡本綺堂・泉鏡花・江戸川乱歩・芥川龍之介・梶井基次郎・小泉八雲・田中貢太郎など）の本が多めに出る。長い本は「死・闇・夜・影・声・独り……」の字がいちばん多いあたりを切り出す。どの本の誰の文章かは「読む」で出る（例：「──『作品名』著者（19xx年に死去）」）。

GitHub につながるかは、Termux で確かめられる。

```sh
cat > ~/boudai-check.sh <<'EOF'
curl -sI https://raw.githubusercontent.com/aozorabunko/aozorabunko/master/index_pages/list_person_all_extended_utf8.zip | head -1
EOF
sh ~/boudai-check.sh
```

`HTTP/2 200` と出れば、ゲームからも取れるはず。

## 遊び方

1. スマホのブラウザ、または Tasker のシーン（WebView）で `boudai-text.html` を開く。
2. 名前を書いて「決定」（書かなくてもいい）。
3. 「命令を作る」→ 動詞 → 言葉（物）の順にタップする。入力欄に日本語で書いてもよい（例：`北`／`雨戸を拾う`／`雨戸を書く`／`燃やす`／`呼ぶ`）。
4. 困ったら「わからない」。

### Tasker で開く

```sh
cat > ~/boudai-tasker.sh <<'EOF'
mkdir -p /storage/emulated/0/Tasker/boudai-text
cp ~/Claude/boudai-text/boudai-text.html /storage/emulated/0/Tasker/boudai-text/
cp /storage/emulated/0/Download/boudai-local.js /storage/emulated/0/Tasker/boudai-text/ 2>/dev/null
EOF
sh ~/boudai-tasker.sh
```

ほかのゲームと同じようにシーンを作り、WebView の Source を `file:///storage/emulated/0/Tasker/boudai-text/boudai-text.html` にする（Mode は `URI`。Allow Phone Access と Allow Universal Access はオン）。

### Tasker を使わずに開く

Download フォルダに `boudai-text.html`（と `boudai-local.js`）を置いて、Termux で次を実行してから、Chrome で `http://localhost:8000/boudai-text.html` を開く（遊んでいるあいだは Termux を閉じない）。

```sh
cd /storage/emulated/0/Download
python3 -m http.server 8000
```

## 音と演出

- 音はブラウザの中で作っている（音声ファイルは使わない）。画面に最初に触れたときから鳴る。≡ メニューの「音と振動」で切れる。
- 低いうなり（暗いほど大きい）、移動の紙をめくる音、×が近づくときの墨を引く音、頁を燃やす音・雪崩の音、つかまったときの衝撃と振動。
- 灯が減るほど画面が暗くなり、灯が消えると字がほとんど見えなくなる。×が近いと画面が細かく震える。
- 深く降りるほど、暗いほど、×が近いほど、字が崩れる（漢字が ×・※・〓・自分の名前の字に化け、同じ字がくり返される）。
- 頁の雪崩：ときどき、何冊ぶんもの文が小さな字でいっぺんに流れこんでくる。

- 目録は `boudai.catalog`、GitHub から取ってきた本は `boudai.works`。

| 呼ぶ | 返事は、本の「 」の中のことば。誰が言ったか（没年つき）が出る。返ってくるのは死んだ人の声だけ |
| 言葉 | 持てるのは五つまで。あふれると、いちばん古いものを忘れる |

終わり方は七つ。

- 一行：最後の頁に自分の名前を書く
- 青空：最後の頁に「青」を含む言葉を書く（どこかの頁で拾っておく）
- 最後の一語：最後の頁にそれ以外の言葉を書く
- 増殖：最後の頁を燃やす
- 未読：最後の頁の上で待ちつづける
- 伏字：×に三度つかまる
- 消灯：灯が消えたまま歩きつづける

## 確認したこと

- このクラウド環境からは GitHub の青空文庫リポジトリにつながらなかったため、本物の青空文庫の本文ではまだ動かしていない。目録の URL・ブランチ名（`master`）・CSV の列名は、知っている形にあわせて書いた。
- かわりに、青空文庫と同じ形（zip に入った CSV 目録と、Shift_JIS の XHTML。ルビ・注記・外字の画像入り）の偽のリポジトリを作り、Chromium（スマホ幅 412px）で確かめた：
  - 目録の zip をほどいて読み、著作権ありの作品を外せること。本文の文字コードを読み分け、ルビ・注記が混ざらないこと
  - 取れない本（404）があっても次の本に移ること。リポジトリにつながらないときは白紙の頁で遊べること
  - 自動で遊ばせて、末尾まで降り、一行・増殖・未読・伏字・消灯の終わりが出ること。青空と最後の一語は、末尾に置いて言葉を持たせた状態から出ることを確かめた
  - ボタンのランダム操作 1500 回で例外が出ないこと、開き直すと続きから始まること
- 手もとの棚：偽の Vault（青空文庫形式の Shift_JIS の txt、前置きつき Markdown、XHTML、ふつうのメモ、隠しフォルダ）で `make-local.py` を走らせ、青空文庫らしい 3 冊だけが拾われ、ルビ・注記が残らないこと。ゲームが localhost と file:// の両方でその棚を使い、GitHub に取りに行かないこと。
- 本物の Vault2 の中身は見ていない（このクラウド環境からは見えない）。ファイルの形が想定と違えば、本が 0 冊になる。
- 実機（Xperia 1 IV のブラウザ、Tasker のシーン）では、まだ確かめていない。
